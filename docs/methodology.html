Methodology

← Back to the explorer

Production data

Field and operator production figures come from NSTA's "UKCS hydrocarbon field production reports PPRS points" dataset, rebuilt weekly. Storage volumes (e.g. Rough) and reporting-unit renames are explicitly separated from production totals, never silently merged. See data/meta.json for the exact source, resolved service URL, and build timestamp behind the figures currently on the site.

Field boundaries

Field outlines shown on the map are NSTA's own authoritative "UKCS petroleum field determinations (WGS84)" polygons — a separate dataset from the production figures above, matched to production field names by exact and normalised name matching only (no fuzzy matching). A field with a matched boundary is shown entirely via its polygon: the polygon's fill is coloured by the field's dominant commodity (the same oil/gas colouring markers used previously), and hovering it shows the same production detail a marker's popup used to show. Not every producing field currently has a matched boundary (matching is measured and recorded in data/meta.json's sources.field_polygons block on every build); a field without a matched polygon is never removed from the map — it falls back to a coloured marker dot instead, exactly as every field was shown before this dataset existed.

Derived production measures (mboe/d)

Alongside NSTA's own native-unit fields (oil and condensate in thousand barrels per day, dry and associated gas in million standard cubic feet per day), every field, operator and equity artifact also carries three derived measures expressed in thousand barrels of oil equivalent per day (mboe/d): liquids_mboed, natural_gas_mboed and total_mboed. These are calculated entirely by this project's build pipeline — NSTA does not publish an mboe/d figure, and nothing on this site should be read as implying it does. The native NSTA fields are unchanged and remain published alongside the derived ones.

The definitions are purely additive:

MeasureFormula
Liquidsliquids_mboed = oil_mbd + condensate_mbd
Natural gasnatural_gas_mboed = (dry_gas_mmscfd + assoc_gas_mmscfd) / 6
Total productiontotal_mboed = liquids_mboed + natural_gas_mboed

Natural gas is converted to barrels of oil equivalent using 6,000 standard cubic feet of gas = 1 boe (recorded as gas_scf_per_boe in data/meta.json and data/equity/meta.json, alongside a production_conversion_methodology version string). This is a conventional energy-equivalence factor, used throughout the oil and gas industry to make gas and liquids volumes comparable on one scale. It is not a claim about the realised energy content, sales specification, or calorific value of gas from any specific UKCS field — actual calorific value varies by field and is not measured or estimated here. Storage volumes are excluded from these derived figures on exactly the same basis they are already excluded from the native production totals (see above); water, injected, flared and vented volumes are never included.

Precision and rounding

Derived values are calculated from full-precision native totals wherever those are available in the pipeline, and rounded to 3 decimal places exactly once, at the point each derived value is written to an artifact. Native component values are never rounded and then re-combined; the one exception is where a derived value must be recomputed from an already-published, already-rounded artifact (for example, cross-checking a field-history artifact's own derived figures against its own serialized native fields), which the build's own conservation checks account for with a small, explicit, documented numerical tolerance rather than treating as exact.

Coverage and availability (equity artifacts)

For equity-attributable derived measures, coverage is production-weighted, not averaged: liquids coverage is the resolved share of total oil-plus-condensate volume for the period; natural-gas coverage is the resolved share of total dry-plus-associated-gas volume for the period. total_mboed availability is component-gated: it is unavailable for a period if either the liquids or the natural-gas component is unavailable for that period; it carries a warning if both components are available but either is below the warning coverage threshold; it is shown as complete only when both components are complete. The combined total_coverage_pct figure is diagnostic only — it is never used to override this component-level gate, so a high blended percentage can never make an unavailable component's contribution to the total appear available. A component whose total reported production for a period is genuinely zero is recorded as not applicable (a known true zero), which is kept distinct from a component that is unresolved or missing data; the total for that period is then driven by the other, producing component alone.

Equity-attributable production

Equity-attributable production is calculated by the weekly build (see data/equity/meta.json for the current build's figures) but is not yet shown anywhere in this site's charts or controls — that is a separate, not-yet-started step. This page documents the methodology behind the artifacts that already exist, ahead of that integration.

Source

Equity-attributable production is calculated from the NSTA dataset whose ArcGIS item is titled “Field Partners”. The NSTA Fields data theme page describes this same dataset as “Current and historical field equity shares”. Both names are recorded as provenance in every build (source_item_title and source_page_description in data/equity/meta.json): the item title is a publisher naming choice, not a description of the data's temporal scope, and the workbook's actual content — dated ownership intervals back to the late 1960s — has been verified directly rather than assumed from either name. Contains information provided by the North Sea Transition Authority and/or other third parties — see the attribution notice in this site's footer and ATTRIBUTION.md.

Interval resolution

Ownership is resolved once per calendar month, at the first day of the month (“month-start”), using half-open intervals: an interest is active for a given month if start_date <= month_start < end_date. An open (blank) end date means the interest is still current. Ownership changing mid-month is attributed entirely to whichever interest was in force on day 1 of that month — never prorated.

Zero-duration and zero-interest rows

A non-trivial share of source rows record an identical start and end date. These are retained as source records but are never treated as an active ownership interval for any month — a zero-duration interval cannot satisfy the half-open test above for any month-start. Separately, some rows record a company's involvement in a field with a recorded interest of 0%. These are also retained as source records but contribute no equity-attributable production, since production multiplied by a 0% share is 0 regardless of the row's other attributes.

Operator status

The source separately records which company operates a field (operator_flag in the field artifacts). Operator status does not imply a positive economic interest — a substantial share of 0%-interest rows belong to the recorded operator. Operator status is never used as a proxy for ownership.

Unresolved field-months

Where a field's ownership records for a given month cannot be resolved cleanly — most commonly because two records genuinely overlap and together claim more than 100% of the field — that field-month is excluded from the calculation entirely, not repaired, normalised back to 100%, or resolved by preferring one recorded owner over another. This is reported in data/equity/anomalies.json, not silently absorbed into any total.

Coverage

Coverage is measured and shown separately for each production stream (oil, dry gas, associated gas, condensate) as the share of that stream's total reported field production for which ownership was cleanly resolved that month. Streams are never combined into a single boe/d figure.

Publication window

Equity ownership records are not evenly available across the production history this site otherwise covers back to 1975. Coverage in earlier years is materially incomplete — the underlying NSTA equity dataset was not populated retroactively to most fields' actual production start dates. Equity-attributable production is therefore published only from March 2013 onward — the earliest month for which coverage was verified to be consistently high across a stable multi-year run, not merely high in one good year.

RuleValue
Fixed publication start2013-03
Minimum coverage to publish a stream-month95%
Coverage below which a warning is shown99.5%

A stream-month below the 95% threshold is never shown as zero — it is represented explicitly as unavailable, with its coverage percentage and exclusion reasons preserved, so a chart shows a gap rather than a misleading flat line. These thresholds apply separately by production stream, never as a single combined figure. The publication start date does not move automatically in later builds; changing it requires an explicit methodology decision and an accompanying test update (see etl/equity_config.py).

MURLACH [pt of MARNOCK-SKUA] — known limitation

This field's only recorded equity rows have an unexplained start date of 2050-01-04. No authoritative evidence links its ownership to the related but distinct MARNOCK [pt. of MARNOCK-SKUA] entry in the source, so none is assumed. MURLACH is excluded from equity-attributable totals until this is resolved by better source evidence; its excluded production is included in stream coverage calculations and fully documented in data/equity/anomalies.json.

Legal entity vs. current display group

Every company name in the equity artifacts is, first and foremost, the legal entity exactly as recorded by NSTA in the source workbook — this is the audit trail and is never altered. A separate, additive dataset (data/equity/groups/) resolves each legal entity to a current display group, sourced primarily from NSTA's own live equity-group-holder field (not a general-purpose corporate-family database); an entity with no such evidence is its own singleton group, never merged on a shared name token alone. This is a current-state-only grouping: it carries no date range, and a current display group is never presented as historically contemporaneous ownership — production shown by current group over historical periods is an analytical regrouping, not a claim about who owned the field at the time. This grouping is surfaced in the Production view's "By company" split, current-group grain, under the same caveat text shown inline there: "Current-group analytical view: historical production has been regrouped using current company relationships. It does not represent company ownership structures at the time." A toggle in that view switches to legal-entity grain, showing each NSTA-recorded legal entity separately with no regrouping. Legal entities with no approved current-group mapping are never dropped from the total — they are shown collapsed into one "Unresolved legal entities" bucket in current-group grain (and individually in legal-entity grain), so unmapped production always remains visible and contributes to the displayed total.

Production overview

The Production view (the site's default landing view) shows UKCS total production in mboe/d, split three ways: Liquids / Natural gas (the default, full production history from 1975, summing every field's derived liquids_mboed and natural_gas_mboed — the same already-published, already-rounded per-field values used elsewhere on this site, never recomputed in the browser); By company (equity-attributable, so restricted to the equity publication window, current-group or legal-entity grain as above); and By field (a selectable Top 5/10/15/20 fields by latest-period production, plus an "Other fields" series defined as UKCS Total minus the sum of the displayed fields' already-published values — the underlying build verifies that summing every field's series reconciles exactly with the UKCS total series, which is what makes that client-side subtraction meaningful rather than an independently-derived, possibly-inconsistent number).

The company-grouping coverage figures shown in this view (approved groups, unresolved entities, latest-period coverage) report distinct approved company groups separately from the count of unresolved legal entities each temporarily standing in for their own one-entity fallback — the two are never combined into one "distinct groups" figure, since a legal entity with no approved mapping is not itself a company group.

Every split in this view also has a Monthly / Annual average toggle, defaulting to Annual average. Annual average is computed entirely in the browser from the same already-published monthly values shown in Monthly mode — no new figure is fetched or derived server-side. A year's value is the mean of only the months actually available that year (a missing/unavailable month is never treated as zero), so a partial year (the current year to date, for example) is still a genuine average of what is known, not diluted by absent months. In the By field split, "Other fields" is defined the same way at either grain — UKCS Total minus the sum of the displayed fields, computed at whichever grain is on screen — so the reconciling identity holds exactly whether viewing monthly or annual figures.

Selecting exactly one company under By company splits that company's own production into categories instead of showing one undifferentiated total: By field (the default, current-group grain only) or Oil vs Gas. Oil vs Gas reuses that company's own already-published liquids_mboed/ natural_gas_mboed values. By field uses a dedicated equity-weighted per-field breakdown, built and reconciled the same way the company totals themselves are (summing every field's contribution reproduces that company's own published total exactly) — not published for legal-entity grain, so the category control offers Oil vs Gas only when viewing an individual legal entity rather than a current company group.

What this figure is not

Equity-attributable production is a gross equity share of reported field production — the field's reported volume multiplied by each company's recorded ownership percentage for that month. It is not net production, working-interest production, or entitlement production: it carries no adjustment for royalty, tax, or any other entitlement mechanism, and should not be read as a substitute for those figures.

Current licence portfolio

The Licence portfolio view's "Current portfolio" sub-view renders the same NSTA licence-subarea-by-equity-holder dataset used for company grouping (data/licence_portfolio.geojson), at subarea grain rather than whole-licence grain, since different subareas of the same licence can have different equity holders. Each subarea polygon's colour AND an "OP"/"NOP" text label both encode operated/non-operated status — colour is never the only signal. The equity holder and operator shown are this source's own current-group-level fields (EQGRPHOLD/OPORGGRP); this dataset does not separately carry a raw legal-entity name distinct from the current group, unlike the equity-production dataset used elsewhere on this site. No area/hectarage figure is shown anywhere in this view: the source geometry is unprojected WGS84 and no projected-CRS area methodology has been implemented or tested, so an area figure would be either wrong or a fabricated-looking precision. The summary metrics shown (distinct licences, distinct subareas, operated/non-operated counts) are computed from the currently filtered set of subareas, not the whole dataset.

"Historical interests" is a placeholder pending a separate historical licence-interest pipeline (not yet implemented) — it will show recorded historical licensee/operator names and geometry by date only, explicitly never a historical equity percentage, which cannot be reconstructed from the published NSTA source.

Historical licence interests and operators

The Licence portfolio view's "Historical licence interests and operators" sub-view uses NSTA's "UKCS offshore petroleum licence blocks history (WGS84)" dataset — the only one of the five licence/block/subarea datasets NSTA publishes with real historical name and date reconstruction (BLCKSTRTDT/BLCKENDDT and the licensee/operator names recorded for each historical licensing episode on a block). Selecting a date shows every recorded episode whose interval contains it (start_date ≤ selected date < end_date; an open end date means the episode is still current). Overlapping or concurrent episodes on the same block are never collapsed or resolved to a single "winner" - all are shown.

This sub-view never shows a historical equity percentage. No NSTA source publishes one: the only dataset with a real, numeric equity split (subareas-by-equity-group-holder, used by the Current portfolio sub-view) is a current-state-only snapshot with no historical variant or effective-date range on the split itself. This is a hard limitation of the published source data, not a gap in this project's pipeline, and the sub-view states this prominently rather than approximating or omitting the caveat.

Known limitation, both datasets

Every check in this project's build is an internal-consistency check against the data it received from NSTA — paginated correctly, counted correctly, internally coherent. None of them can independently verify that what NSTA served was itself complete. A service returning a dataset that is internally consistent but silently incomplete is not detectable by this pipeline. This is an open, unmitigated gap for both the production and equity sources, not a solved one.
